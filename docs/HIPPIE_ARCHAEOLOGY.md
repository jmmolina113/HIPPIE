# HIPPIE archaeology report

## Scope and provenance

The source is the archive `X-ray Pinhole Imaging Pipeline .zip` on the mounted
Molina Drive. It is approximately 4.0 GB and contains 1,377 archive entries:
MATLAB generations, calibration and shot HDF5 files, filter tables, workbooks,
PowerPoint documentation, PDFs, and PlasmaPy notebooks. The source archive is
being treated as read-only.

The MATLAB lineage is the scientific reference. The Python notebooks are a
later port and are evidence of intended behavior, not an authority when they
disagree with the MATLAB code.

## Reconstructed lineage

### SULI 2021: establish the measurement

The first pipeline reads pre-shot and shot HDF5 images, subtracts the
background, floors negative values, flat-fields against a calibration image,
isolates two neighboring pinholes, aligns their lineouts, and compares their
filtered signal ratio to a model ratio over a log-spaced temperature grid.

The 2021 README already states the operational contract: pinhole row/column
conventions, left/center/right analysis regions, filter naming, and the paired
filter thickness inputs.

### PPPL 2022: make the work reusable

The “New Pipeline” separates ingestion, calibration, pinhole selection,
alignment, lineout generation, transmission curves, theory integration, and
temperature inversion. It also introduces explicit upper/nominal/lower
transmission and signal-ratio bounds.

The code remains a working research bench: absolute paths, hard-coded image
geometry, exploratory plotting, stale scripts, and partially developed
rotation support are all present.

### Spring 2023: promote the lineout method to a map

The 2D pipeline retains the same physics but computes a ratio at every spatial
bin. It adds target-edge detection, image-space error shifts, binning, and
temperature-map post-analysis. `testForVicente_JMM_Answer.m` is the clearest
near-user-facing MATLAB example and supplies the cleanest parameter contract.

### PlasmaPy: port and interaction

The notebooks reproduce the main stages in Python and add manual alignment
widgets. The port is syntactically valid, but it still carries legacy
assumptions such as 1051-pixel coordinates, manual paths, and incomplete error
bound propagation in the primary temperature-map entry point.

## Scientific contract

For two pinholes with different filter responses, the measured ratio is

`S(x, y) = signal_high_filter(x, y) / signal_low_filter(x, y)`.

The theoretical curve is generated by integrating an emissivity model weighted
by the detector response and the filter transmission, then taking the ratio of
the two pinholes. Temperature is obtained by finding the temperature whose
theoretical ratio best matches the measured ratio.

The pipeline therefore has five scientifically meaningful boundaries:

1. raw detector counts -> calibrated counts;
2. calibrated image -> two canonical pinhole images;
3. two pinholes -> registered pair;
4. registered pair -> measured ratio and uncertainty bounds;
5. measured ratio + response model -> electron temperature.

## What the code reveals about the design process

The work is empirical in the best research sense. Each generation attacks the
largest visible failure mode:

- smoothing was moved to a larger patch when shifted-image boundaries created
  artificial maxima;
- peak-based alignment grew into target-edge fitting when simple maxima were
  not stable enough;
- alignment became iterative when one correction disturbed the other axis;
- lineout uncertainty became image-space shifts in the 2D version;
- hand-selected regions became explicit temperature maps and averaging tools;
- the notebooks added manual controls where automation could not yet be
  trusted.

The recurring comments about “no pipeline is perfect,” smoothing sensitivity,
manual alignment, and benchmarking against Thomson scattering are not side
notes; they are the project’s uncertainty model in embryonic form.

## High-priority defects to resolve during the port

- `EstimateElectronTemperature_2D.m` requires `parametersLocation`, while
  several older drivers call it without that argument.
- `mainTemperatureCalculation_allTimes.m` contains stale calls and uses
  `params` before assigning it in at least one case.
- `MakeProcessedData_v2.m` constructs a rotation matrix but never applies it.
- `iterativePinholeAlignment_2D_v2.m` labels horizontal and vertical shift
  booleans in the opposite order.
- Fixed 4200/6200/1050/500 geometry is embedded throughout selection and
  alignment.
- Parameter lookup does not fail clearly when a shot key is absent.
- Filter loading relies on `eval` and the current MATLAB working directory.
- Error bounds are partly geometric, partly signal-based, and not represented
  as a named uncertainty object.

These are porting targets, not silent corrections to the historical result.
The Python implementation must first reproduce the legacy behavior, then offer
opt-in corrected behavior with explicit comparison reports.

## Documentation recovered from the Alexandria corpus

The local Library of Alexandria index contains a Magnetic Reconnection Project
collection with `MolinaJacob_Abstract.pdf`, `MolinaJacob_Slides.pdf`, and the
analysis figures `Analysis1`, `Analysis2`, `Answer_noErr`, `Answer_w_Err`, and
related measurement diagrams. The extracted notes describe the same pipeline:
background subtraction, flat-fielding, unit-cell partitioning, pinhole-pair
isolation, alignment, normalization, ratio formation, model integration, and
error propagation.

The SULI final report was subsequently recovered as a local source copy. Its
six-page account confirms the lineout-era calibration, registration, response
integration, inversion, and uncertainty workflow, including the distinction
between unresolved early-time points and measured zero temperature. See
[`SULI_2021_REPORT.md`](SULI_2021_REPORT.md). The source PDF remains outside the
public repository.
